## 0. О документе

Документ описывает, **что** строим и **как**, достаточно подробно, чтобы любой разработчик или ИИ-ассистент
мог продолжить работу без доступа к истории переписки. Прогресс и следующий шаг — в `docs/PROGRESS.md`.

Предыстория: в папке лежит прототип PWA (`index.html`, `app.js`, `styles.css`, `service-worker.js`,
`manifest.webmanifest`) и ещё более ранний одностраничный прототип `la_hiphop_radio_player_v3.html`.
Они задают **настроение** (Санта-Моника, бумбокс, неоновые столбики) и стартовый список из 6 станций,
но архитектурно заменяются этим проектом. Найденные в прототипе ошибки перечислены в PROGRESS.md
(раздел «Уроки прототипа») — их нельзя повторять.

## 1. Видение, сценарии, границы

### 1.1 Видение

Быстрый, лёгкий плеер, в котором **все бесплатные радиостанции Лос-Анджелеса собраны по жанрам**.
Открыл → выбрал жанр → выбрал станцию → играет. Выглядит и ощущается как магнитола/бумбокс 80-х:
сегментные столбики эквалайзера, «частотное» табло, механические ползунки. Работает на телефоне
(в том числе в машине) и на компьютере.

### 1.2 Пользовательские сценарии

| # | Сценарий | Где |
|---|----------|-----|
| S1 | Сел в машину, телефон подключился по Bluetooth — продолжает играть последняя станция | Android |
| S2 | В машине за 2 касания: плитка жанра → станция | Android (Car mode / Android Auto) |
| S3 | Кнопками на руле переключаю станции внутри жанра | Android (MediaSession) |
| S4 | Убавляю басы и добавляю верха 5-полосным эквалайзером, сохраняю пресет | Android, веб |
| S5 | Смотрю, как столбики «прыгают» в такт музыке | Android, веб |
| S6 | Плохой интернет — переключаю «Экономию» (или «Авто» делает это сам), музыка не рвётся | Android, веб (частично) |
| S7 | Добавляю станцию в избранное, избранное — первая вкладка | Android, веб |
| S8 | Ищу станцию iHeartRadio по названию или вставляю ссылку — она добавляется в мою коллекцию | Android, веб |
| S9 | На компьютере открываю сайт/PWA, слушаю с тем же эквалайзером и визуализатором | веб |
| S10 | Вижу, что сейчас играет (исполнитель — трек), если станция это сообщает | Android, веб |
| S11 | Таймер сна: выключить через 30/60 мин | Android, веб |

### 1.3 Не-цели (сознательно не делаем)

- Вход в аккаунт iHeartRadio логином/паролем, синхронизация их избранного (см. §9).
- Запись эфира, скачивание треков.
- Платные/DRM-сервисы (SiriusXM и т.п.).
- Публикация в Google Play на первом этапе (возможно позже; архитектура не мешает).
- Публичный сервис для других людей с ретрансляцией эфиров (юридические причины, §11).

### 1.4 Нефункциональные требования

- **Старт воспроизведения:** ≤ 3 с на хорошей сети (от нажатия до звука).
- **Размер APK:** ≤ 15 МБ. **Веб-бандл:** ≤ 300 КБ JS (gzip) без шрифтов.
- **Фон:** Android продолжает играть при выключенном экране, не убивается системой (foreground service).
- **Батарея:** визуализатор не рисуется при выключенном экране / свёрнутом приложении.
- **Офлайн-старт:** приложение открывается без сети и показывает каталог из кэша (звука, понятно, нет).
- **Доступность:** контраст, крупные цели касания (≥ 48 dp), поддержка «уменьшить движение».

## 2. Обзор архитектуры

```
                ┌──────────────────────────────────────────────┐
                │  catalog/  (Node.js + TS, GitHub Actions)     │
                │  curated.yaml + Radio Browser API             │
                │  → объединение → проверка потоков             │
                │  → dist/stations.json  (GitHub Pages)         │
                └──────────────────────┬───────────────────────┘
                                       │ HTTPS GET раз в сутки / при старте
                  ┌────────────────────┴─────────────────────┐
                  │                                          │
     ┌────────────▼─────────────┐              ┌─────────────▼────────────┐
     │  android/                │              │  web/                     │
     │  Compose UI (MVVM)       │              │  Svelte UI                │
     │  MediaController ◄──┐    │              │  AudioEngine (Web Audio)  │
     │                     │    │              │   <audio> → 5×Biquad →    │
     │  PlaybackService    │    │              │   Gain → Analyser → out   │
     │  (MediaLibraryService)   │              │  Service Worker (PWA)     │
     │   ExoPlayer         │    │              │  Media Session API        │
     │   ├ EqProcessor (5 полос) │              └─────────────┬────────────┘
     │   └ FftTapProcessor ─┘    │                            │ аудио через relay
     │  Room (избранное, кэш)    │              ┌─────────────▼────────────┐
     │  DataStore (настройки)    │              │  relay/  (Node.js + TS)   │
     │  Android Auto (дерево)    │              │  HTTPS + CORS для потока  │
     └────────────┬─────────────┘              │  ICY «что играет» → JSON  │
                  │ напрямую                    │  опц. транскодинг ffmpeg  │
                  ▼                             └─────────────┬────────────┘
        ┌──────────────────────────────────────────────────────▼─────┐
        │  Радиостанции: StreamTheWorld, Abacast, iHeart (HLS/AAC),   │
        │  Icecast/Shoutcast серверы, публичное радио (KCRW, KUSC…)   │
        └─────────────────────────────────────────────────────────────┘
```

**Ключевые принципы:**

1. **Каталог — данные, а не код.** Список станций живёт в одном JSON, оба клиента его читают. Добавить станцию = поправить `curated.yaml`.
2. **Android ходит к станциям напрямую** — ему CORS не мешает, звук обрабатывается внутри ExoPlayer.
3. **Веб ходит через relay** — иначе браузер не даст обрабатывать звук (EQ и визуализатор) и не даст играть HTTP-потоки на HTTPS-странице.
4. **Веб деградирует плавно:** если relay недоступен — играет напрямую через `<audio>`, но EQ выключен, а визуализатор в «декоративном» режиме (честно помечен).
5. **Общий дизайн** через `design/tokens.json`: одинаковые цвета, частоты полос EQ, параметры столбиков.

## 3. Выбор технологий

### 3.1 Решение

| Часть | Технология | Почему |
|-------|-----------|--------|
| Android UI | Kotlin, Jetpack Compose, Material 3 (сильно перекрашенный) | Современный стандарт, Canvas для визуализатора |
| Android звук | **AndroidX Media3**: ExoPlayer + `MediaLibraryService` + `MediaSession` | Фон, уведомление, Bluetooth/руль, Android Auto, HLS, ICY-метаданные из коробки |
| Android DSP | Собственные `AudioProcessor` в ExoPlayer: EQ (biquad) + FFT-отвод | Одинаковые полосы с вебом, не нужен микрофон, работает на любом устройстве |
| Android данные | Room (избранное, свои станции, кэш каталога), DataStore (настройки) | Стандарт |
| Android сеть | OkHttp (используется и ExoPlayer через `OkHttpDataSource`), kotlinx.serialization | Один HTTP-стек |
| Android DI | Ручной DI (`AppContainer`) | Проект маленький, Hilt избыточен |
| Веб UI | Vite + Svelte 5 + TypeScript | Минимальный бандл, быстро |
| Веб звук | Web Audio API (`BiquadFilterNode`, `AnalyserNode`) | Нативно в браузере |
| Веб PWA | `vite-plugin-pwa` (Workbox) | Установка, офлайн-оболочка |
| Каталог | Node.js 20+ + TypeScript, запуск в GitHub Actions по расписанию | Бесплатно, без своего сервера |
| Хостинг каталога и веба | GitHub Pages (или Cloudflare Pages) | Бесплатно, HTTPS |
| Relay | Node.js 20+ + TypeScript (без фреймворка или Fastify), ffmpeg (опц.), Docker | Простой стриминг-прокси |
| Хостинг relay | Docker на дешёвом VPS или домашний ПК + Cloudflare Tunnel | Минимальная стоимость |

### 3.2 Рассмотренные и отклонённые варианты

| Вариант | Почему нет |
|---------|-----------|
| Одна PWA + обёртка (Capacitor/TWA) | По сути веб-вьюшка; нет нормального Android Auto, проблемы с фоном, EQ упирается в CORS |
| Flutter (Android + Web + Desktop) | Один UI-код, но EQ/визуализатор всё равно пишутся отдельно под каждую платформу; `just_audio` даёт EQ только на Android; веб-сборка Flutter тяжёлая |
| Kotlin Multiplatform + Compose Web (Wasm) | Тяжёлый веб-бандл, аудио в вебе всё равно через JS-интероп; избыточно для двух небольших клиентов |
| React Native | Те же проблемы с нативным аудио, плюс мост JS↔натив |
| Системный `android.media.audiofx.Equalizer` | Число полос и частоты зависят от устройства, на части прошивок работает плохо; оставлен как запасной вариант |
| Системный `android.media.audiofx.Visualizer` | Требует разрешения на запись звука (микрофон) — пугает пользователя |

## 4. Каталог станций

### 4.1 Источники

1. **`catalog/curated.yaml`** — ручной список ключевых станций LA с правильными жанрами, частотами, ссылками на официальный плеер. Ручные данные имеют приоритет.
2. **Radio Browser API** (`https://de1.api.radio-browser.info`, список зеркал через `all.api.radio-browser.info`) — открытая бесплатная база. Запрос: `GET /json/stations/search?countrycode=US&state=California&hidebroken=true&limit=500`, дальше фильтр по LA-региону (по полям `geo_lat`/`geo_long` в радиусе ~80 км от центра LA (34.05, -118.25), либо по городу/тегам). Поля: `stationuuid`, `name`, `url`, `url_resolved`, `codec`, `bitrate`, `hls`, `tags`, `homepage`, `favicon`, `lastcheckok`, `geo_lat`, `geo_long`. Обязательно передавать понятный `User-Agent` (например `SantaMonicaRadio/0.1`).
3. **Пользовательские станции** (iHeart по ссылке/поиску, ручной URL) — хранятся только локально у пользователя, в общий каталог не попадают.

### 4.3 Схема `stations.json` (schemaVersion 1)

```jsonc
{
  "schemaVersion": 1,
  "generatedAt": "2026-11-08T03:00:00Z",
  "region": { "id": "la", "name": "Los Angeles", "center": [34.05, -118.25] },
  "genres": [
    { "id": "hiphop", "name": "Hip-Hop", "nameRu": "Хип-хоп", "order": 1, "color": "#67ff91" }
  ],
  "stations": [
    {
      "id": "kpwr",                       // стабильный id: позывной в нижнем регистре или slug
      "name": "POWER 106",
      "callsign": "KPWR",
      "frequency": "105.9 FM",            // строка для табло; для интернет-станций — "WEB"
      "city": "Los Angeles",
      "genres": ["hiphop"],
      "description": "Hip-Hop",
      "logo": "https://…/kpwr.png",       // может быть null; клиент рисует ретро-заглушку с частотой
      "homepage": "https://www.power106.com/",
      "officialPlayer": "https://player.listenlive.co/44031/",
      "source": "curated",                // curated | radiobrowser
      "radioBrowserUuid": null,
      "streams": [
        {
          "url": "https://playerservices.streamtheworld.com/api/livestream-redirect/KPWRFM.mp3",
          "format": "mp3",                // mp3 | aac | hls | ogg | opus
          "bitrate": 128,                 // кбит/с, null если неизвестно
          "quality": "high",              // high | medium | low  (для выбора качества)
          "https": true,
          "icy": true,                    // поток отдаёт ICY-метаданные
          "check": { "ok": true, "at": "2026-11-08T03:00:00Z", "latencyMs": 640, "contentType": "audio/mpeg" }
        }
      ],
      "status": "ok"                      // ok | degraded | dead  (dead не показывается клиентам)
    }
  ]
}
```

Правила:
- `streams` отсортированы от лучшего качества к худшему внутри каждого `quality`.
- Станция без рабочих потоков, но с `officialPlayer` — получает `status: "degraded"`; клиент показывает кнопку «Официальный плеер».
- Обратная совместимость: клиент игнорирует неизвестные поля; при `schemaVersion` больше известной — использует встроенную копию каталога и показывает «обновите приложение».

### 4.4 Формат `curated.yaml`

```yaml
- id: kpwr
  name: POWER 106
  callsign: KPWR
  frequency: 105.9 FM
  genres: [hiphop]
  homepage: https://www.power106.com/
  officialPlayer: https://player.listenlive.co/44031/
  streams:
    - url: https://playerservices.streamtheworld.com/api/livestream-redirect/KPWRFM.mp3
      quality: high
    - url: https://playerservices.streamtheworld.com/api/livestream-redirect/KPWRFMAAC.aac
      quality: medium
  notes: "StreamTheWorld; mount KPWRFM"
```

### 4.5 Пайплайн сборки (`catalog/src`)

1. `fetch-radiobrowser.ts` — скачать станции Калифорнии, отфильтровать LA-регион, нормализовать.
2. `merge.ts` — объединить с `curated.yaml`: совпадение по `callsign`, затем по нормализованному имени; ручные поля важнее; дубли убрать.
3. `resolve.ts` — развернуть плейлисты `.pls` / `.m3u` в прямые URL; для StreamTheWorld понимать формат `livestream-redirect/<MOUNT>.<ext>`.
4. `check.ts` — для каждого потока: `GET` с заголовком `Icy-MetaData: 1`, таймаут 8 с, прочитать первые ~32 КБ, записать `content-type`, `icy-br`, `icy-metaint`, время до первого байта; `hls` — скачать мастер-плейлист и перечислить варианты битрейта. Параллельность 8.
5. `classify.ts` — проставить `quality` по битрейту: ≥ 96 кбит/с → high, 48–95 → medium, < 48 → low; HLS → `high` с адаптацией.
6. `build.ts` — собрать `dist/stations.json` + `dist/report.md` (что умерло, что появилось).
7. GitHub Actions `catalog.yml`: по расписанию раз в сутки + вручную; публикует `dist/` на GitHub Pages.

Клиенты: при старте берут удалённый каталог (кэш 24 ч), при ошибке — локальный кэш, при его отсутствии — копию, встроенную в сборку (`assets/stations.json` в APK, `public/stations.json` в вебе).

### 4.6 Известные адреса потоков (из прототипа, проверить)

| Станция | Потоки |
|---------|--------|
| POWER 106 | `…/livestream-redirect/KPWRFM.mp3`, `…/KPWRFMAAC.aac` (StreamTheWorld) |
| 93.5 KDAY | `…/livestream-redirect/KDAYFM.mp3` |
| CALI 93.9 | `…/livestream-redirect/KLLI_FMAAC.aac`, `…/KLLI_FMAAC_SC` |
| 102.3 KJLH | `http://stream.abacast.net/direct/kjlh-kjlhfmaac-ibc2` (только HTTP!) |
| REAL 92.3, KIIS 102.7 | только iHeart (см. §9) |

Префикс StreamTheWorld: `https://playerservices.streamtheworld.com/api/livestream-redirect/`.
Справочно: `https://playerservices.streamtheworld.com/api/livestream?version=1.9&mount=<MOUNT>&lang=en` возвращает XML со списком серверов — запасной способ, если redirect перестанет работать.

## 5. Android-приложение

### 5.1 Базовые параметры

- `applicationId`: `app.smradio` (рабочее, см. открытые вопросы).
- `minSdk` 26 (Android 8.0), `targetSdk`/`compileSdk` — последний стабильный на момент начала.
- Язык интерфейса: английский + русский (`values-ru`). Названия станций не переводятся.
- Одна Activity (`MainActivity`) + Compose Navigation.
- Сборка: Gradle Kotlin DSL, version catalog `gradle/libs.versions.toml`. Версии библиотек — последние стабильные на момент создания проекта (записать в PROGRESS.md).

```
    └── settings/
```

Если проект разрастётся — выделить `:core:dsp` и `:core:catalog` в отдельные модули. Не раньше.

### 5.3 Воспроизведение

- `PlaybackService : MediaLibraryService`, внутри один `ExoPlayer`.
- `ExoPlayer` строится с:
  - `OkHttpDataSource.Factory` (общий OkHttpClient, `User-Agent: SantaMonicaRadio/<версия>`);
  - `DefaultRenderersFactory`, у которого переопределён `buildAudioSink(...)`, чтобы вернуть `DefaultAudioSink.Builder(context).setAudioProcessors(arrayOf(eqProcessor, fftTapProcessor)).build()`;
  - `setAudioAttributes(USAGE_MEDIA, CONTENT_TYPE_MUSIC, handleAudioFocus = true)`;
  - `setHandleAudioBecomingNoisy(true)` — пауза при отключении наушников/Bluetooth;
  - `setWakeMode(C.WAKE_MODE_NETWORK)`;
  - `DefaultLoadControl` с буфером из настроек (§10).
- Каждая станция — `MediaItem` с `mediaId = station.id`, `MediaMetadata` (название, частота, жанр, логотип). URI выбирает `StreamSelector`.
- **Фолбэк потоков:** при `onPlayerError` — следующий поток станции; когда кончились — статус «станция недоступна» + кнопка «Официальный плеер» (открывает браузер). Таймаут на старт — **8 секунд**, а не 1,5 (урок прототипа).
- **«Что играет»:** `Player.Listener.onMediaMetadataChanged` / `onMetadata` → `IcyInfo.title` (формат обычно `Artist - Title`) → обновить `MediaMetadata` сессии (видно в уведомлении, на экране блокировки, в машине).
- **Переключение станций кнопками «вперёд/назад»** (руль, наушники): плейлист сервиса = станции текущего жанра (или избранного), `seekToNext/Previous` переключают станцию.
- UI подключается к сервису через `MediaController` (`SessionToken`).

### 5.4 DSP: эквалайзер и спектр

**Обе обработки внутри ExoPlayer, над декодированным PCM 16-бит**, до вывода в динамик.

`EqAudioProcessor` (наследник `BaseAudioProcessor`):
- принимает `C.ENCODING_PCM_16BIT`, любое число каналов и частоту;
- 5 фильтров на канал (параметры одинаковые с вебом, из `tokens.json`):

| Полоса | Частота | Тип | Q |
|--------|---------|-----|---|
| 1 | 60 Гц | low-shelf | 0.707 |
| 2 | 230 Гц | peaking | 1.0 |
| 3 | 910 Гц | peaking | 1.0 |
| 4 | 3.6 кГц | peaking | 1.0 |
| 5 | 14 кГц | high-shelf | 0.707 |

- усиление каждой полосы −12…+12 дБ, шаг 0.5 дБ;
- автоматический преамп: `preamp = -max(0, max(gains)) * 0.8` дБ — чтобы подъём полос не перегружал;
- мягкий лимитер на выходе (tanh-клиппер выше −1 dBFS);
- коэффициенты по RBJ Audio EQ Cookbook, пересчёт при смене настроек атомарно (без щелчков — плавное изменение коэффициентов за ~20 мс);
- флаг `enabled`; при выключении процессор неактивен (`isActive = false`) — ноль нагрузки.

`FftTapProcessor`:
- пропускает звук без изменений, копирует моно-сумму в кольцевой буфер;
- каждые ~33 мс (30 кадров/с) берёт окно 1024 отсчёта, окно Ханна, FFT (своя реализация radix-2 или маленькая библиотека, например JTransforms — если вес приемлем);
- раскладывает спектр на **N полос визуализатора** (по умолчанию 16) логарифмически от 40 Гц до 16 кГц;
- переводит в дБ, нормализует (−60…0 дБ → 0…1), публикует в `SpectrumBus` (`MutableStateFlow<FloatArray>`);
- **работает только когда UI видим** (флаг от `Lifecycle` UI) — экономия батареи;
- сервис и UI в одном процессе, поэтому достаточно синглтона `SpectrumBus` в `AppContainer`.

Запасной вариант EQ: если собственный процессор вызовет проблемы, можно подключить системный `android.media.audiofx.Equalizer` к `player.audioSessionId` (число полос зависит от устройства; привести к 5 ближайшим).

### 5.5 Android Auto

- В манифесте: сервис с `intent-filter` `androidx.media3.session.MediaLibraryService` и `android.media.browse.MediaBrowserService`; `meta-data com.google.android.gms.car.application` → `res/xml/automotive_app_desc.xml` с `<uses name="media"/>`.
- `LibraryTree`: корень → «Избранное», «Недавние», «Жанры» → жанр → станции (`isPlayable = true`, артворк = логотип или сгенерированная ретро-плитка).
- Поиск голосом: `onSearch` / `onGetSearchResult` — поиск по названию и позывному.
- **Важно для установки не из Play Market:** в Android Auto на телефоне включить режим разработчика (10 нажатий на «Версия»), затем в настройках разработчика включить «Неизвестные источники». Иначе приложение не появится на экране машины.
- Тестирование без машины: Desktop Head Unit (DHU) из Android SDK.

### 5.6 Car mode (без Android Auto, просто Bluetooth)

- Отдельный экран: тёмный, крупные плитки (минимум 96 dp), 2×3 жанра, затем крупный список станций, огромные «⏮ ⏯ ⏭».

### 5.8 Экраны (описание для реализации)

1. **Home:** сверху «частотное табло» с последней станцией и кнопкой ▶; ниже вкладки «Избранное / Жанры / Недавние»; жанры — сетка плиток 2 колонки с цветной полоской жанра.

8. **Car mode:** см. §5.6.

### 6.3 Аудио-граф

```
<audio crossOrigin="anonymous" src="https://relay/s/<stationId>?q=<quality>&t=<token>">
   → MediaElementAudioSourceNode
   → Biquad(60, lowshelf) → Biquad(230) → Biquad(910) → Biquad(3600) → Biquad(14000, highshelf)
   → GainNode (преамп)
   → DynamicsCompressorNode (как мягкий лимитер)
   → AnalyserNode (fftSize 2048, smoothing 0.6)
   → AudioContext.destination
```

- `AudioContext` создаётся/возобновляется только по жесту пользователя (политика автовоспроизведения).
- **Критично:** `MediaElementAudioSourceNode` для потока без CORS выдаёт **тишину** без ошибки (это и сломало прототип). Поэтому граф подключается **только** для URL relay. Без relay — прямое `<audio>` без графа, EQ недоступен (UI показывает «EQ доступен через сервер»), визуализатор в режиме `decorative` (псевдо-анимация, помеченная иконкой).
- Фолбэк потоков: событие `error` или нет `playing` за 8 с → следующий поток.
- «Что играет»: опрос `GET relay/np/<stationId>` раз в 10 с (или SSE).

### 6.4 PWA и хостинг

- Service Worker кэширует оболочку и шрифты (precache), `stations.json` — stale-while-revalidate, аудио **никогда** не кэшируется.
- Хостинг: GitHub Pages (`/web` собирается в Actions) или Cloudflare Pages. HTTPS обязателен.
- Установка на Windows: Chrome/Edge → «Установить приложение».
- Горячие клавиши: пробел — play/pause, ←/→ — станция, 1–9 — избранное.

## 7. Ретранслятор (relay)

### 7.1 Зачем

1. Отдать поток браузеру с заголовками CORS → работают EQ и визуализатор.
2. Отдать HTTP-потоки по HTTPS → не блокируется mixed content.
3. Читать ICY-метаданные (браузер их не видит) → «что играет».
4. (Опционально) пережимать поток в низкий битрейт для плохой сети.

Android relay **не использует** (кроме, возможно, функции транскодинга в будущем).

### 7.2 API

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/health` | `{"ok":true,"version":"…"}` |
| GET | `/s/:stationId?q=high|medium|low&i=<индекс потока>&t=<token>` | Проксирует поток станции из каталога. Upstream-запрос с `Icy-MetaData: 1`; метаданные вырезаются из аудио, клиенту идёт чистый поток. Заголовки ответа: `Access-Control-Allow-Origin: <origin веба>`, `Content-Type` как у источника, `Cache-Control: no-store`. |
| GET | `/np/:stationId` | `{"title":"Artist - Track","at":"…"}` — последние метаданные (обновляются, пока кто-то слушает; иначе relay коротко подключается сам). |
| GET | `/t/:stationId?br=48&t=<token>` | (опц.) Транскодинг через ffmpeg в AAC-ADTS/MP3 с заданным битрейтом (32/48/64). |
| GET | `/iheart/search?q=…` , `/iheart/station/:id` | (экспериментально) серверный вызов неофициального iHeart API, §9. |

### 7.3 Безопасность

- **Только станции из каталога** (allowlist по `stationId` → URL берётся из `stations.json`, клиент URL не передаёт). Пользовательские станции веба — через подписанный параметр или отдельный allowlist в конфиге.
- Простой токен доступа (`RELAY_TOKEN` в `.env`), передаётся параметром `t` (для `<audio>` нельзя задать заголовок).
- CORS только для своего домена веба и `localhost` при разработке.
- Ограничение: не более N одновременных потоков (по умолчанию 4).
- Логи без IP-адресов слушателей.

### 7.4 Реализация

- Node.js 20+, TypeScript, `undici`/`fetch` для upstream, ручной парсер ICY: читать `icy-metaint`, каждые `metaint` байт идёт байт длины ×16 и блок `StreamTitle='…';`.
- Разворачивание `.pls/.m3u`, следование редиректам (StreamTheWorld отдаёт 302).
- Отмена upstream при закрытии клиентом соединения (иначе утечки).
- Dockerfile (node:20-alpine + ffmpeg опционально), `docker-compose.yml`.
- Деплой: VPS (любой дешёвый) или домашний ПК + Cloudflare Tunnel (без открытия портов). Ограничение: при хостинге дома трафик идёт через домашний канал.

### 8.3 Визуализатор (спецификация поведения, одинаковая для обеих платформ)

- **16 столбиков × 12 сегментов** (на узком экране — 12 столбиков). Между сегментами зазор, сегменты прямоугольные со скруглением 1–2 px.
- Вход: массив уровней 0…1 по логарифмическим полосам 40 Гц–16 кГц (Android — из `FftTapProcessor`, веб — из `AnalyserNode.getByteFrequencyData`).
- **Динамика как у реальных индикаторов:** быстрый подъём (`level = max(level, input)` с коэффициентом `attack`), медленное падение (`releasePerSec` сегментов в секунду).
- **Пиковые «шапочки»:** запоминают максимум, держатся `peakHoldMs`, затем падают со скоростью `peakFallPerSec`.
- Верхние 2 сегмента — цвет `hot` (жёлтый/красный), как на магнитофонах.
- Погасшие сегменты видны цветом `dim` (эффект реального дисплея).
- 30 кадров/с; при «уменьшить движение» — 10 кадров/с без пиков.
- **Режим `decorative`** (нет доступа к PCM — веб без relay): уровни генерирует плавный шум с «пульсом» ~ 95 BPM; показывается маленький значок «≈», чтобы не выдавать за настоящий спектр.
- Отрисовка: Android — Compose `Canvas` (одна функция `drawRect` на сегмент, без рекомпозиции на каждый кадр: состояние читается внутри `drawBehind`/`Canvas`); веб — `<canvas>` 2D + `requestAnimationFrame`.

## 9. iHeartRadio

### 9.1 Факты

- **Публичного API для сторонних разработчиков у iHeartRadio нет.** Существуют неофициальные адреса, которыми пользуется их собственный сайт; они могут измениться без предупреждения.
- Вход в аккаунт через неофициальный API = нарушение их условий использования, риск блокировки аккаунта пользователя, и приложению пришлось бы хранить пароль. **Поэтому авторизацию не делаем.**
- Многие **живые эфиры** iHeart доступны без входа — их поток можно получить по id станции.

### 9.2 Что реализуем (фаза 7, помечено «экспериментально»)

1. **Добавление по ссылке.** Пользователь вставляет ссылку вида `https://www.iheart.com/live/real-923-181/` → извлекаем числовой id (последнее число в slug: `181`).
2. **Получение потоков:** `GET https://api.iheart.com/api/v2/content/liveStations/<id>` → в ответе (ожидается) объект `streams` с полями вроде `secure_hls_stream`, `secure_shoutcast_stream`, `hls_stream`, `shoutcast_stream`, `pls_stream`. Предпочтение: `secure_hls_stream` → `secure_shoutcast_stream`. **Структуру ответа проверить при реализации** и зафиксировать в PROGRESS.md.
3. **Поиск по названию:** через неофициальный поиск iHeart (точный адрес выяснить при реализации, посмотрев запросы сайта iheart.com в DevTools) — если не получится, поиск только по ссылке.
4. Добавленная станция сохраняется как **пользовательская** (`origin = "iheart"`, в Room / localStorage) и попадает в избранное и выбранный жанр.
5. Ссылки iHeart периодически перепроверяются (при запуске раз в неделю); если поток умер — кнопка «Открыть в iHeartRadio».
6. Веб: запросы к api.iheart.com делаются через relay (CORS).

### 9.3 Что остаётся за официальным приложением iHeartRadio

Персональные подборки, подкасты, синхронизация избранного с аккаунтом. Официальное приложение iHeart и так работает в Android Auto.

## 10. Качество потока и плохая сеть

### 10.1 Ограничение

Битрейт радиопотока задаёт станция. Клиент не может «убавить» его у готового потока — только выбрать другой вариант или получить пережатый поток с сервера.

### 10.2 Механизмы

1. **Варианты в каталоге:** у станции может быть несколько потоков `high/medium/low` (например MP3 128k и HE-AAC 48k у StreamTheWorld).
2. **HLS:** ExoPlayer сам выбирает вариант по пропускной способности (`DefaultTrackSelector`), при «Экономии» ограничиваем `setMaxAudioBitrate`.
3. **Транскодинг на relay** (`/t/...`): 32/48/64 кбит/с. Для Android — опция «Через сервер (экономия)» в будущем.

### 10.3 Настройка «Качество»

| Значение | Поведение |
|----------|-----------|
| Авто (по умолчанию) | Wi-Fi → high; мобильная сеть → medium; при ≥ 2 буферизациях за 60 с — шаг вниз; после 10 мин без проблем — шаг вверх (только при следующем запуске станции, без разрыва) |
| Высокое | Всегда лучший поток |
| Среднее | medium, иначе ближайший |
| Экономия | low, иначе самый низкий битрейт |

### 10.4 Настройка «Буфер»

| Профиль | minBuffer / maxBuffer / startPlayback | Для чего |
|---------|---------------------------------------|----------|
| Быстрый старт | 5 с / 20 с / 1 с | Хорошая сеть |
| Баланс (по умолчанию) | 15 с / 50 с / 2.5 с | Обычно |
| Стабильный (машина) | 30 с / 120 с / 5 с | Дорога, туннели, слабая связь |

Индикатор качества в плеере: точка-LED (зелёная/жёлтая/красная) + битрейт текущего потока, например `AAC 48k`.

## 11. Правовые ограничения

- Приложение воспроизводит **публично доступные** бесплатные потоки станций, как любой интернет-радиоплеер. Логотипы и названия станций принадлежат владельцам; использовать их только для идентификации станции.
- **Relay — для личного использования** (доступ по токену). Публичная ретрансляция чужих эфиров может нарушать авторские права и условия станций.
- Не обходить DRM, не встраивать официальные плееры в чужую обёртку, не подделывать брендинг станций.
- Шрифты — только с открытой лицензией (OFL). Иконки — свои или с открытой лицензией.
- Название приложения не должно повторять бренды (iHeart, KIIS и т.п.).

## 12. Тестирование и критерии качества

### 12.1 Автоматические тесты

- `catalog`: юнит-тесты merge/classify; JSON Schema валидация `stations.json` в CI.
- Android: юнит-тесты `Biquad` (АЧХ на контрольных частотах ±0.5 дБ), `StreamSelector`, раскладки спектра; инструментальный smoke-тест запуска сервиса.
- Веб: Vitest для `catalog.ts`, раскладки спектра; Playwright smoke (страница открывается, станция стартует через мок-поток).
- Relay: тест парсера ICY на записанном фрагменте потока.

### 12.2 Ручной чек-лист перед релизом версии

- [ ] Каждая станция каталога стартует ≤ 3 с (Wi-Fi) на Pixel.
- [ ] Выключенный экран 30 минут — звук не прерывается.
- [ ] Bluetooth-наушники: пауза при отключении, кнопки работают.
- [ ] Android Auto (DHU или машина): дерево жанров, переключение станций, «что играет».
- [ ] EQ: Bass Cut заметно убирает бас, без щелчков при движении фейдера, без перегруза на +12 дБ.
- [ ] Визуализатор реагирует на музыку и тишину (на разговорной станции видно отличие).
- [ ] Режим «Экономия» реально выбирает низкий битрейт (видно в индикаторе).
- [ ] Офлайн-запуск: каталог виден, понятное сообщение «нет сети».
- [ ] Веб: Chrome и Edge на Windows; EQ и визуализатор работают через relay; без relay — играет, EQ честно недоступен.

## 13. Риски

| Риск | Вероятность | Что делаем |
|------|-------------|-----------|
| Адреса потоков меняются | высокая | Ежедневная автопроверка каталога, несколько потоков на станцию, кнопка официального плеера |
| Неофициальный iHeart API ломается | высокая | Фича помечена экспериментальной, изолирована в одном модуле, при ошибке — «Открыть в iHeartRadio» |
| CORS / mixed content в вебе | гарантирован без relay | Relay; плавная деградация |
| Собственный DSP грузит процессор старых телефонов | низкая | Biquad дёшев; FFT только при видимом UI; запасной системный Equalizer |
| Android Auto не видит sideload-приложение | средняя | Инструкция «Неизвестные источники» в настройках разработчика AA |
| Лимиты/смена ассистента посреди работы | средняя | AGENTS.md + PROGRESS.md, маленькие шаги, обновление журнала в конце каждой сессии |
| Стоимость relay | низкая | Только личное использование, лимит одновременных потоков, домашний ПК + Cloudflare Tunnel |

## 14. Глоссарий

- **APK** — установочный файл Android-приложения.
- **PWA** — веб-приложение, которое можно «установить» из браузера, работает офлайн-оболочкой.
- **Media3 / ExoPlayer** — официальная библиотека Google для воспроизведения медиа на Android.
- **MediaSession** — механизм Android, через который плеером управляют уведомление, экран блокировки, наушники, руль, Android Auto.
- **CORS** — правило браузера: страница может обрабатывать данные с чужого сайта, только если тот разрешил это заголовком.
- **Mixed content** — блокировка HTTP-ресурсов на HTTPS-странице.
- **ICY-метаданные** — встроенная в поток Shoutcast/Icecast строка «что сейчас играет».
- **HLS** — потоковый формат из коротких сегментов с несколькими вариантами битрейта.
- **Biquad** — простой цифровой фильтр второго порядка; из пяти таких состоит эквалайзер.
- **FFT** — быстрое преобразование Фурье; превращает звук в спектр для столбиков.
- **Relay** — наш маленький сервер-посредник для веб-версии.
- **DHU** — Desktop Head Unit, эмулятор экрана Android Auto на компьютере.
- **VFD** — вакуумно-люминесцентный дисплей, светящиеся сегменты на технике 80-х.
